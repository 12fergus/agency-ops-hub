# Database schema

Source of truth: `apps/api/src/db/schema.ts` → generated SQL in `apps/api/migrations/` (`0000_init.sql`).
Procedure for changing it: [operations.md](operations.md#schema-changes).

## Conventions (binding for every migration)

| Topic                  | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IDs                    | `text` UUIDv7, generated by the server (`lib/ids.ts`). Never client-supplied. Time-ordered, but sort by `created_at`.                                                                                                                                                                                                                                                                                                                                      |
| Timestamps             | UTC ISO-8601 text with ms, e.g. `2026-11-20T10:00:00.000Z` (same as `Date#toISOString`). **Every timestamp column has a `CHECK … GLOB` enforcing exactly this format**, so string order equals time order. Offsets (`+02:00`) and zoneless values are rejected. Services convert input with `toUtcIso` (zoneless input → 422). DB default `strftime('%Y-%m-%dT%H:%M:%fZ','now')`; `updated_at` is set by Drizzle on update. UI converts to Asia/Jerusalem. |
| Booleans               | `integer` 0/1.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Enums                  | `text` + `CHECK (col IN (...))`. The TS union comes from the same constant.                                                                                                                                                                                                                                                                                                                                                                                |
| Foreign keys           | Every relationship. `PRAGMA foreign_keys = ON` on every connection; the app refuses to start if it can't be enabled. **No `ON DELETE CASCADE`** anywhere — history is never deleted implicitly.                                                                                                                                                                                                                                                            |
| Same-client invariants | Enforced twice: (1) **composite FKs** in the DB, (2) service checks that return `CROSS_CLIENT_REFERENCE` (422).                                                                                                                                                                                                                                                                                                                                            |
| Deletion               | Business records are archived (`archived_at`), not deleted. Hard delete is an admin maintenance operation outside the MVP.                                                                                                                                                                                                                                                                                                                                 |
| Email                  | Stored trimmed + lowercase; `CHECK (email = lower(trim(email)))`. This gives case-insensitive uniqueness on `users.email` without `COLLATE NOCASE` (see ADR-006).                                                                                                                                                                                                                                                                                          |
| Phone                  | `phone_raw` stored exactly as entered; `phone_normalized` (E.164-like) only for duplicate matching, `NULL` when it can't be normalized safely. **Never unique.**                                                                                                                                                                                                                                                                                           |
| Secrets                | Only hashes are stored (`password_hash`, `token_hash`). Audit snapshots drop any key matching password/token/secret/hash/api key/cookie. **Lead and task audits store only IDs and state**, never name, phone, email, description or free text (`auditLeadView`).                                                                                                                                                                                          |

## Tables

### users

`id`, `email` (unique, normalized), `display_name`, `password_hash`, `role` (`admin|manager|employee`), `is_active` (default 1), `created_at`, `updated_at`.
Disabled accounts are `is_active = 0`, never deleted. Until the auth phase, users get the placeholder hash `!unusable`, which no password can match.

### sessions

`id`, `user_id` → users, `token_hash` (unique; the server stores only the hash), `created_at`, `expires_at`, `revoked_at`, `last_seen_at`. Indexes: `user_id`, `expires_at` (for cleanup).

### clients

`id`, `name`, `business_name`, `status`, `status_id` → client_statuses, `industry`, `phone`, `email`, `notes`, `photo_type`, `photo_updated_at`, timestamps, `archived_at`.

- **`status` is the lifecycle only.** The app writes `active` or `archived`. `paused` is still allowed by the original CHECK, but since 0002 it is no longer written. CHECK: `status = 'archived'` ⇔ `archived_at IS NOT NULL`.
- **`status_id`** is the admin-defined business status (פעיל, לא פעיל, …), set to the default on creation. It was added in 0002 as a nullable column without a table rebuild; the app always sets it.
- **`photo_type`** (`image/png|jpeg|webp`) and **`photo_updated_at`** describe the photo/logo file at `<UPLOADS_DIR>/clients/<id>.<ext>`. NULL means no photo.
- Indexes: `(status, name)`, `status_id`.

### client_statuses (0002)

`id`, `name` (unique, 1–40), `color` (CHECK, a palette of `green gray amber blue red purple teal pink`), `position` (display and sort order), `is_default` (**exactly one**, via a partial unique index), timestamps.

- Seeded: פעיל (green, default), לא פעיל (gray), מושהה (amber).
- A status that is in use, or is the default, can't be deleted (enforced by the service).

### client_members

PK `(client_id, user_id)`, `membership_role` (`owner|collaborator`), `created_at`. Index `user_id` (to answer "which clients can this user see").

### client_contacts

`id`, `client_id`, `name`, `title`, `phone`, `email`, `is_primary`, timestamps. **At most one primary per client** (partial unique index `WHERE is_primary = 1`); the service clears the old primary in the same transaction.

### pipelines / pipeline_stages

`pipelines`: `id`, `client_id`, `name` (unique per client), `is_default` (**one default per client**, partial unique index), timestamps. `UNIQUE (id, client_id)` is the target of the leads composite FK.
`pipeline_stages`: `id`, `pipeline_id`, `name` (unique per pipeline), `position` (≥ 0, unique per pipeline), `stage_type` (`open|won|lost`), `color`. `UNIQUE (id, pipeline_id)` is the composite FK target.
Each new client gets a default pipeline: חדש → בטיפול → ממתין למענה → נסגר בהצלחה (won) → לא רלוונטי (lost).

### campaigns

`id`, `client_id`, `name`, `channel` (`meta|google|tiktok|organic|other`), `external_id`, `is_active`, timestamps. `external_id` is unique per `(client_id, channel)` only when present. `UNIQUE (id, client_id)` is the composite FK target.

### leads

`id`, `client_id`, `pipeline_id`, `stage_id`, `campaign_id?`, `import_batch_id?`, `assigned_user_id?` → users, `full_name`, `phone_raw`, `phone_normalized`, `email`, `source` (`manual|web_form|csv_import|meta|google|tiktok|whatsapp|phone|referral|other`), `source_external_id?`, `consent_status` (`unknown|granted|denied`), `consent_at`, `description`, timestamps, `archived_at`.

Composite FKs (DB-enforced same-client rules):

| FK                                                                    | Guarantees                                                          |
| --------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `(pipeline_id, client_id)` → `pipelines(id, client_id)`               | pipeline belongs to the lead's client                               |
| `(stage_id, pipeline_id)` → `pipeline_stages(id, pipeline_id)`        | stage belongs to the lead's pipeline (so also to the client)        |
| `(campaign_id, client_id)` → `campaigns(id, client_id)`               | campaign belongs to the client (skipped when `campaign_id` is NULL) |
| `(import_batch_id, client_id)` → `lead_import_batches(id, client_id)` | import batch belongs to the client                                  |

Assignee access (admin, or a member of the client) is checked in services, not in the DB, because admins are not members.

Unique: `(client_id, source, source_external_id)` when `source_external_id` is present (idempotent ingestion later). `UNIQUE (id, client_id)` is the target of the tasks composite FK.
Indexes: `(client_id, created_at)`, `(client_id, stage_id)`, `(client_id, assigned_user_id)`, `(client_id, phone_normalized)`, `(client_id, email)`, `(assigned_user_id)`.
**Duplicates**: same client + same `phone_normalized` or `email` → a warning returned by `createLead`. Never blocked.

### lead_activities

`id`, `lead_id`, `actor_user_id`, `type` (`note|call|whatsapp|email|meeting|stage_change`), `body`, `occurred_at`, `metadata_json` (CHECK `json_valid`), `created_at`. Index `(lead_id, occurred_at)`.

### tasks

`id`, `client_id`, `lead_id?`, `assigned_user_id`, `title`, `description`, `due_at` (UTC), `status` (`open|done|cancelled`), `completed_at`, timestamps.
Composite FK `(lead_id, client_id)` → `leads(id, client_id)`. CHECK: `completed_at` is set exactly when `status = 'done'`.
Indexes: `(assigned_user_id, status, due_at)` for "my overdue work", `(client_id, status, due_at)`, `lead_id`.

### lead_import_batches

`id`, `client_id`, `actor_user_id`, `file_name`, `rows_total`, `rows_created`, `rows_skipped`, `created_at`. CHECK: counts ≥ 0 and `created + skipped ≤ total`.

### audit_events

`id`, `actor_user_id?`, `client_id?`, `entity_type`, `entity_id`, `action`, `before_json`, `after_json` (both CHECK `json_valid`), `created_at`. Indexes: `(client_id, created_at)`, `(entity_type, entity_id)`, `(actor_user_id, created_at)`. Written in the same transaction as the change it describes.

### Not in this migration

`ingestion_events` (P1 webhooks) arrives with the webhook phase.

### client_communications (0003)

`id`, `client_id`, `contact_id` (nullable), `author_user_id`, `type` (`call|whatsapp|meeting|email|note`), `occurred_at` (UTC), `summary` (1–5000), timestamps.

- **Composite FK** `(contact_id, client_id)` → `client_contacts(id, client_id)`, so the contact always belongs to the same client. It is backed by the new unique index `client_contacts_id_client_unique`.
- **Deleting a contact** clears `contact_id` on its records; the records themselves stay.
- **Indexes:** `(client_id, occurred_at)`, `contact_id`, and unique `(id, client_id)`, which is the target of the task FK.

### tasks (rebuilt in 0003)

- **New columns:** `created_by_user_id` → users (nullable; NULL for older tasks), `communication_id` (nullable).
- **Link to a record:** composite FK `(communication_id, client_id)` → `client_communications(id, client_id)`, so a follow-up task always belongs to the record's client.
- **Status** CHECK: `open|in_progress|done|cancelled`. CHECK: `status = 'done'` ⇔ `completed_at IS NOT NULL`.
- **Migration 0003** rebuilds the table (SQLite can't alter a CHECK in place) and keeps every existing row, covered by a test. Nothing references `tasks`, so the rebuild runs safely inside the migration transaction.
